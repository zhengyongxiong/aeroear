# 智能耳压适应系统 · 手机应用方案（v1.0 讨论定稿）

> 设备：挂脖主机（XIAO ESP32-S3 + BMP390 环境气压）+ 左右耳塞气路（柔性气管 / 透气防水膜 / 微型电磁阀 / 耳塞后腔压力传感器）
> App 能看到的数据：环境气压、左右耳道（耳塞后腔）气压、估算海拔、阀门动作、预测趋势

## 1. 讨论纪要（关键分歧与结论）

**议题 1：App 到底测的是什么？**
- ENT：耳塞后腔测到的是**外耳道气压**，不是中耳气压。耳闷来自鼓膜两侧（外耳道 vs 中耳）的压差，中耳压力靠咽鼓管调节，设备测不到。
- ALG：所以控制目标应定为"让外耳道气压以个人可承受的速率跟随环境"，给咽鼓管留出反应时间，而不是"消除压差"。
- **结论**：App 文案统一用"耳道气压 / 耳塞内外压差"，不出现"中耳压力""治疗"等字样；产品定位为**舒适辅助设备**，非医疗器械。

**议题 2：预测放在手机还是设备？**
- APP：手机算力强，模型好迭代。
- FW：飞行中手机可能锁屏、BLE 断开；电梯场景几秒内就要决策，链路延迟不可接受。
- **结论**：**预测与控制全部在设备端运行**；手机负责可视化、个人参数配置、反馈收集、数据存档和离线模型调参，参数下发到设备。断连时设备按最后一次参数继续工作。

**议题 3：安全兜底**
- ENT：耳塞密封 + 阀门故障常闭 = 外耳道被"锁"在旧气压，降落时可能比不戴更难受，甚至造成气压伤。
- FW：阀门选**断电常开**型；若只能用常闭阀，固件需在低电量、看门狗复位、传感器异常时强制开阀；透气膜本身保留被动慢速泄压通道。
- **结论**：设置硬限制——任一侧耳塞内外压差超过上限立即全开阀门，该逻辑优先级高于一切算法，App 不可关闭（只能在"实验模式"中调整阈值且需二次确认）。默认阈值需由医学顾问确认后写入。

**议题 4：左右耳参数怎么来？**
- PM：用户不懂"时间常数"。
- UX：用问卷 + 每次使用后打分，App 内只展示"敏感度 / 适应速度"两个滑块和一句话解释。
- ALG：问卷给初值，打分做小步更新，每次调整幅度设上限，避免一次不好的体验把参数推飞。
- **结论**：见第 4 节"个人参数模型"。

**议题 5：是否提示用户做吞咽/捏鼻鼓气？**
- ENT：可以提示吞咽、打哈欠、咀嚼；**捏鼻鼓气（Valsalva）不主动推荐**，感冒/鼻塞时用力鼓气有风险，最多在帮助页说明正确做法和注意事项。
- **结论**：在预测到快速变压前 10–30 秒，轻震动 + 提示"可以吞咽一下"，用户可关闭。

**议题 6：海拔怎么显示？**
- ALG：气压换算海拔在机舱内得到的是**座舱高度**（通常 1800–2400 m 当量），不是飞机高度；天气变化也会让地面读数漂移几十米。
- UX：标注为"估算海拔"，飞行模式下标为"座舱等效海拔"。
- **结论**：提供可选的海平面气压（QNH）校准：联网时取当地气象数据，或用户手动输入已知海拔。

**议题 7：先做什么？**
- QA：下一步是真空箱实验，最急需的是"能记录、能打标记、能 A/B、能导出"的工具。
- **结论**：v0.1 先做**实验模式**，消费者功能放到后面（见第 9 节路线图）。

## 2. 产品定位

- **一句话**：在气压快速变化前提前动作，按左右耳各自的节奏，让耳道气压"慢慢跟上"。
- **目标场景**：乘机起降、高速电梯、山区驾车/高铁隧道。**不支持**潜水等水下场景。
- **目标用户**：起降时易耳闷、左右耳感受不一致的人群。
- **禁忌提示（首次使用必读）**：鼓膜穿孔、中耳炎/外耳道炎急性期、置管术后、近期耳部手术、严重感冒鼻塞——请先咨询医生。出现耳痛、耳鸣加重、听力下降、眩晕，立即取下并就医。

## 3. 功能与页面

### 3.1 信息架构

```
底部 Tab：  实时 │ 行程 │ 我的耳朵 │ 记录
其他入口：  设备设置、实验模式（开发者开关）、帮助与安全
```

### 3.2 页面说明

**① 实时（首页）**
- 顶部：连接状态、电量、当前模式（自动/飞行/电梯/手动/实验）。
- 主视觉：左右两个"耳朵卡片"，各显示耳塞内外压差（hPa）+ 舒适状态色带（绿/黄/红）+ 阀门状态。
- 中部：环境气压、变化速率（hPa/min）、估算海拔。
- 下部：最近 5 分钟曲线（环境 + 左 + 右三条线），曲线右侧以虚线延伸显示**预测趋势**及置信带。
- 事件提示条："预计 20 秒后开始快速升压（下降中）"。

**② 行程**
- 一键开始"飞行 / 电梯 / 自驾山路"行程，设备切换对应预测策略。
- 飞行模式自动识别阶段：地面 → 爬升 → 巡航 → 下降 → 落地，在时间轴上标出。
- 行程结束后弹出 10 秒反馈：左右耳分别 0–3 分不适 + 可选"哪个阶段最难受"。

**③ 我的耳朵**
- 左右耳分开设置：敏感度、适应速度（滑块，带白话解释）。
- 首次问卷（≈6 题）：哪边更容易闷、通常多久缓解、是否常感冒鼻塞等。
- 参数变化历史（让用户看到"系统在学习"）。
- "恢复默认"与"左右对调"按钮。

**④ 记录**
- 行程列表 → 详情页：三条压力曲线、阀门动作甘特条、预测线、反馈评分、关键指标。
- 导出 CSV / 分享。

**⑤ 实验模式（v0.1 核心）**
- 开关：预测 开/关；左右参数对调；手动指定左右参数。
- 打标记按钮（"开始减压""回压""异常"），带自由文本备注。
- 高频原始数据录制（设备端 50 Hz，见第 6 节）。
- 实验组管理：同一实验下多次运行自动编号，便于 A/B 对比。
- 一键导出：原始数据 CSV + 实验元数据 JSON。

### 3.3 UI 规范要点（UX）
- **左蓝右红**：沿用听力图惯例（左耳蓝、右耳红），并始终带 "L / R" 文字，照顾色弱用户。
- 机舱弱光场景：默认深色模式，核心数字 ≥ 32pt，单手可操作。
- 状态用"舒适 / 注意 / 不适风险"三级，不直接展示吓人的专业词。
- 预测内容一律带"预计"字样和置信带，避免用户把预测当事实。
- 震动提示 > 声音提示（用户可能在戴耳塞）。

## 4. 算法方案（ALG）

### 4.1 海拔估算
```
h = 44330 × (1 − (P / P0)^(1/5.255))      P0 默认 1013.25 hPa，可用 QNH 校准
```
近海平面约 1 hPa ≈ 8.3 m。

### 4.2 短时预测（设备端）
分两层，先简单、可解释，再逐步加复杂度：

1. **状态估计**：卡尔曼滤波，状态 = [气压, 变化速率, 变化加速度]，去除走动、开关门等噪声。
2. **场景/阶段识别**：规则状态机（速率阈值 + 持续时间），识别电梯运行、飞机爬升/下降。
3. **趋势外推**：
   - 电梯：预测时域 3–15 s，按当前速率与加速度外推，并利用"电梯会减速停下"的先验。
   - 飞行：预测时域 30 s–3 min，座舱压力变化通常平缓且近似恒速，按阶段先验 + 速率外推。
4. **后续迭代**：用积累的真实数据训练轻量模型（如小型 GRU / 梯度提升树），先在手机端离线评估，确认优于基线后再量化部署到 ESP32-S3。

输出：未来 N 秒气压预测值 + 置信区间 + 事件（"即将快速升压"）。

### 4.3 个人参数模型（每只耳朵独立）

| 参数 | 含义 | 控制中的作用 |
|---|---|---|
| `rate_max` | 可承受的耳道气压最大变化速率 (hPa/min) | 限制耳道气压跟随环境的速度 |
| `dp_comfort` | 舒适压差带宽 (hPa) | 压差在此范围内不必急着放气 |
| `lead_time` | 提前动作时间 (s) | 预测到变压后提前多久开始交换 |

- **来源**：问卷 → 初值（落在安全区间内的几档预设）。
- **更新**：每次行程反馈后，若某耳不适评分高 → 该耳 `rate_max` 下调、`lead_time` 增加；连续多次舒适 → 小幅回调。每次变化 ≤ 10%，且始终限制在上下界内。
- **"以往不适体验"**：按阶段记录（如"下降阶段右耳常不适"），对该阶段单独加权，而不是全局调整。
- 所有参数改动记录版本，可回滚。

### 4.4 控制律
- **前馈**：根据预测轨迹和 `lead_time` 提前规划开阀节奏。
- **反馈**：以实测耳塞内外压差为输入，计算阀门 PWM 占空比（开/关时长），使耳道气压按 `rate_max` 跟随目标轨迹。
- **硬限制**：|压差| > 安全阈值 → 立即全开（固件最高优先级）。
- 左右两路完全独立计算，共用同一份环境预测。

## 5. 硬件与固件要点（FW）

- **耳道压力测量**：每个耳塞后腔需一个独立压力传感器。BMP390 I²C 地址只有 0x76/0x77 两个，三颗传感器需改用 SPI 或加 I²C 多路复用器；耳塞内也可选更小封装的气压芯片。
- **采样**：传感器 50 Hz + 内部 IIR 滤波；控制环 50 Hz；BLE 上报 10 Hz（实验模式 50 Hz）。
- **阀门**：优先选断电常开阀；驱动加续流二极管；记录每次开关时间戳。
- **兜底**：看门狗、低电量强制开阀、传感器读数异常（卡死/跳变）强制开阀。
- **本地存储**：设备 Flash 循环记录 1 Hz 摘要，断连期间不丢数据，重连后补传。
- **OTA**：ESP32-S3 支持 BLE/Wi-Fi OTA，便于算法迭代。

## 6. 缓存与上下文长度设计

"上下文"指预测模型看多久的历史、各层数据保留多久。原则：**设备端只留决策需要的最短窗口，手机端按用途分级降采样**。

| 位置 | 缓冲 | 采样率 | 长度 | 用途 |
|---|---|---|---|---|
| 设备 RAM | 预测输入窗口 | 50 Hz | 10 s（500 点） | 电梯级快速预测 |
| 设备 RAM | 趋势窗口 | 1 Hz | 300 s（300 点） | 飞行阶段识别、慢趋势 |
| 设备 RAM | BLE 发送队列 | — | 2 s | 抗短时丢包 |
| 设备 Flash | 断连补传日志 | 1 Hz | 12 h 循环覆盖 | 断连期间不丢数据 |
| 手机内存 | 实时曲线 | 10 Hz | 最近 10 min | 首页图表，超出即丢 |
| 手机 SQLite | 行程数据 | 1 Hz（实验模式保留原始） | 按行程永久，可设上限 | 记录、反馈、导出 |
| 手机 SQLite | 参数与反馈历史 | 事件驱动 | 永久 | 个人参数学习 |

- 预测窗口长度作为可配置参数下发，实验中对比 5 / 10 / 20 s 的效果再定。
- 手机端行程超过 90 天自动降采样为 0.2 Hz 摘要（原始数据可先导出）。

## 7. 通信协议（BLE GATT，APP + FW）

自定义 Service，包含以下 Characteristic：

| 名称 | 属性 | 内容 |
|---|---|---|
| Telemetry | Notify | 实时数据包（见下） |
| Control | Write | 模式切换、预测开关、左右对调、手动开阀、打标记 |
| Profile | Read/Write | 左右耳参数（带版本号） |
| LogTransfer | Notify/Write | 断连日志分块补传 |
| DeviceInfo | Read | 固件版本、电量、传感器状态 |

**Telemetry 数据包（20 字节，适配默认 MTU）**

| 字段 | 类型 | 说明 |
|---|---|---|
| seq | u16 | 序号，检测丢包 |
| t_ms | u32 | 设备时间戳 |
| p_amb | u32 | 环境气压，0.01 Pa |
| dp_L | i16 | 左耳塞内外压差，0.1 Pa |
| dp_R | i16 | 右耳塞内外压差，0.1 Pa |
| duty_L | u8 | 左阀占空比 0–100 |
| duty_R | u8 | 右阀占空比 0–100 |
| pred_slope | i16 | 预测速率，0.1 Pa/s |
| state | u8 | 模式/阶段 |
| flags | u8 | 阀状态位、安全触发、预测开关、左右对调 |

（BLE 链路层自带 CRC，包内不再单独加校验字节，共 20 字节。）

海拔由手机端根据 `p_amb` 计算，不占带宽。

## 9. 真空箱实验支持（QA）

**实验矩阵**
1. 预测 关 vs 开（同一气压曲线、同一参数），每组 ≥ 5 次重复。
2. 左右参数对调前后各一组。
3. 气压曲线：电梯式快速变化、飞行式慢速变化、阶跃。

**指标（App 自动计算并导出）**
- 每侧峰值压差 |ΔP|max
- 超阈值压差的时间积分（"不适负荷"）
- 耳道气压最大变化速率 vs 设定的 `rate_max`
- 预测提前量：阀门首次动作时间 − 环境开始快速变化时间
- **对调一致性**：对调后左曲线与对调前右曲线的相关系数和均方根误差（越接近越能说明差异化控制真实有效）

**数据格式**：CSV 列 = `t_ms, p_amb, p_L, p_R, duty_L, duty_R, pred_on, swapped, marker`，另附 JSON 记录固件版本、参数、箱体曲线配置。
